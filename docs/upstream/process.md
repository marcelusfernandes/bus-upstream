# Processo de Product Upstream

O upstream é um loop orientado a gaps epistemológicos, não uma sequência fixa.

```text
Intake → Assess Problem + Solution → escolher gap crítico → skill/subagent
      → evidência/artefato/decisão → re-assess → registrar transição ↺
      → Problem Ready + Solution Deliver → independent readiness review
      → delivery package
```

## Intake

A entrada pode ser hipótese, oportunidade, reclamação, métrica, pedido de
stakeholder, solução já sugerida, research ou risco. Preserve o texto inicial.

## Autonomia

O orchestrator pode pesquisar, criar framing, gerar alternativas, testar
assumptions com evidência disponível, registrar follow-ups e compilar tracking.
Ele para nos human gates.

## Re-assessment

Depois de qualquer evidência ou decisão material, use `$upstream-assess`.
Transições não precisam seguir ordem única.
